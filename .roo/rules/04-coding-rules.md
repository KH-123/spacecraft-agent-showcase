# Coding and Project Rules

Purpose: define implementation and collaboration rules. Keep this file short.

## Tech Stack

Use:

- Python
- Streamlit
- local Markdown / text knowledge files
- optional simple local retrieval
- optional OpenAI-compatible LLM API
- environment variables for secrets

Keep the project lightweight.

## Hard Rules

1. Do not hard-code test examples.
2. Do not perform broad rewrites unless explicitly requested.
3. Do not modify unrelated files.
4. Do not change existing `tools/` interfaces unless explicitly requested.
5. Keep UI, agent logic, RAG, and deterministic tools separated.
6. Keep LLM extraction separate from validation and tools.
7. Keep RAG separate from normalization, inference, consistency checks, and tools.
8. Do not hard-code API keys.
9. Use `.env` or environment variables for secrets.
10. After code changes, explain how to run and test.

## Preferred Structure

Core files:

- `app.py`
- `agents/`
- `tools/`
- `docs/`

- `demo_cases/`

Important docs:

## Document Ownership

`docs/project_status.md`

- Current-state entry point.
- Must stay short.
- Update after every code-changing round.
- Include current features, current pipeline, known issues, next step.

`docs/change_log.md`

- Recent-only changelog.
- Update after every code-changing round.
- Keep only recent important changes.

`docs/archive/change_log_archive.md`

- Long-term history.
- Do not read by default.
- Read only for historical debugging or review.

`docs/handoff_to_roo.md`

- Mainly generated by Codex.
- Roo Code treats it as implementation instructions.

`docs/handoff_to_codex.md`

- Mainly generated by Roo Code.
- Update when Codex should review, diagnose, or continue work.

`docs/bug_summary.md`

- Update only when a bug cannot be fixed within two attempts.

## Token-saving Rules

Default read set before most tasks:

- `.roo/rules/`
- `AGENTS.md`
- `docs/project_status.md`
- current handoff file if relevant

Do not read by default:

- full repository
- full `docs/change_log.md`
- `docs/archive/change_log_archive.md`
- unrelated source files
- old handoff files

Use task-specific minimal reads:

- workflow change: `app.py` and relevant `agents/`
- RAG change: `rag_retriever.py`, `design_advisor.py`, `docs/rag_knowledge/`
- tools change: specific `tools/` file and its caller
- UI change: `app.py` and related display helpers
- docs change: relevant docs only

Do not paste full source files into handoff docs.

Do not duplicate rules already in `.roo/rules/` or `AGENTS.md`.

Do not use changelog as project context. Use `docs/project_status.md`.

## change_log Policy

`docs/change_log.md` should stay short.

When it becomes long:

1. Move older entries to `docs/archive/change_log_archive.md`.
2. Keep only recent important entries in `docs/change_log.md`.
3. Do not delete historical information.
4. Do not require Roo Code to read archive by default.

## Required Checks

After code changes, run:

`python -m py_compile app.py agents/*.py`

Then update:

- `docs/project_status.md`
- `docs/change_log.md`

If only docs changed, compilation is optional.

Run app with:

`streamlit run app.py`
